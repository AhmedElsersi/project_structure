## 1. Architecture pattern

"Clean-architecture-lite" as the project's CLAUDE.md calls it: **layer-first data/domain** with **feature-first presentation**.

- `lib/data/` holds `datasources/` (Hive boxes, sqflite DBs, asset readers; each an `abstract class` plus an `…Impl` that throws `AppException`), `models/` (Equatable, hand-written `fromMap`/`toMap`/`parse`, no codegen) and `repositories/` (abstract + `…Impl` returning `Future<Either<Failure, T>>`, catching `AppException` and mapping it via `failureFromException`).
- `lib/domain/` holds `entities/` (SessionConfig, PlanStep, PlaybackUnit, ReviewCard, HifzPlan…) and `engine/` (RepetitionPlanBuilder, ReviewScheduler, HifzPlanner: pure Dart with zero Flutter imports). There are no use-case classes: cubits call repositories and engines directly.
- `lib/services/` holds cross-feature services: network fetchers (remote JSON, fonts, images), audio pipeline (resolver, storage, pack downloads, player, media session) and platform-channel wrappers (share, file pick, keep awake).
- `lib/features/<feature>/` holds `cubit/` (Cubit + Equatable state), `screen/` and `widgets/`. A screen creates its cubit with `BlocProvider(create: (_) => sl<XCubit>()..load())`.
- `lib/core/` holds the cross-cutting pieces: theme, router, DI, error types, localization keys, constants, extensions, shared widgets.
- `lib/admin/` + `lib/main_admin.dart` is a separate macOS-only internal tool (audio splitting and publishing). The app entrypoint never imports it, and a test enforces this by walking the import graph.

A feature is a cubit/state pair plus a screen, and sometimes private widgets. State is a single Equatable class with a `LoadStatus` field and `copyWith`. The cubit takes repositories as named constructor args and is registered as a `factory` in GetIt.

## 3. Infrastructure

### State management
- `flutter_bloc ^9.1.1`, **Cubit only** (no Bloc events), with no base cubit class. States are Equatable with `copyWith`, and most use `LoadStatus` (`lib/core/state/load_status.dart`: `initial/loading/ready/failure` + `isLoading/isReady/isFailure`).
- App-wide cubits (`SettingsCubit`, `UpdateCubit`) are provided above `MaterialApp.router` with `lazy: true`, so nothing is created before `AppBootstrap` finishes. `main.dart` follows theme changes with a stream subscription and `setState` instead of a BlocBuilder, which keeps the widget tree shape stable.
- Patterns: generation counter against stale async results (`SearchCubit._generation`), `isClosed` checks after awaits, and a multi-writer settings sync (`SettingsRepository.changes` broadcast that `SettingsCubit` follows, ignoring its own echoes by identity).
- Quality: good discipline. The big cubits (`session_cubit.dart` 1260 lines, `mushaf_cubit.dart` 614) are heavy.

### DI
- `get_it ^9.2.1`, set up by hand in `lib/core/di/injection.dart` (`final GetIt sl = GetIt.instance;`, `configureDependencies()`).
- Rule: `registerLazySingleton` for data sources, repositories and services (with `dispose:` callbacks for stream controllers and http clients); `registerFactory` for cubits. Hive-backed data sources are opened eagerly (`await x.open()`) before registration. Platform calls (the audio_service media session) are deliberately left out of DI and started from `AppBootstrap`, so tests can run `configureDependencies` as is.
- Smell: DI imports `features/home/screen/home_shell.dart` for `HomeTabs` (a ValueNotifier defined in a screen file).

### Routing
- `go_router ^18.0.1`. `AppRoutes` holds path and name constants. `AppRouter.create()` builds a new router for each app instance (not a static one) so history doesn't leak between tests.
- Splash uses a `CustomTransitionPage` with zero forward duration and a 300 ms reverse fade. `_leaveSplash` waits up to 1 s for settings to be read, then `go`es to onboarding or home.
- Settings sub-pages are nested routes, so back returns to settings. Typed args travel in `state.extra` (`state.extra! as int`, `as AyahRef`), so those routes don't work as deep links. One path param (`/surah/:surahNumber/progress`) is parsed with a thrown `ArgumentError`.
- No redirect guards, no deep-link package.

### Networking
- `http ^1.2.0`, public GETs only (contract rule A.2.3). No interceptors, auth, or token refresh.
- `AppInfoService` and `ManifestService` share the same shape. `load()` answers from the disk cache or the bundled asset, then calls `unawaited(refresh())`. `refresh()` does a GET with a 5 s timeout, accepts only a 200 response whose JSON parses to something non-empty, writes the cache atomically (`.part` + rename), and emits on a broadcast `changes` stream. All failures are swallowed.
- `ReciterImageCache` fetches each image once (10 s timeout) to app-support/images with an atomic write, deduplicating in-flight lookups in a `Map<String, Future<File?>>`.
- `QpcFontService` fetches gzipped per-page fonts, checks length and then sha256 against a bundled list, registers them with `FontLoader`, and retries after a minute on failure.
- `AudioPackService`/`PackFetcher` download zips through `background_downloader`, check size before sha256, and unzip with `archive`.
- Errors: services never throw for network failures. `runZonedGuarded` in `main.dart` drops uncaught `SocketException/HttpException/TlsException` (logged with `developer.log`) and forwards everything else to `FlutterError.reportError`.
- URLs come from `lib/core/constants/cdn.dart` (`String.fromEnvironment` with a hardcoded default `{{BASE_URL}}`).

### Local storage
- `hive_ce ^2.19.3` + `hive_ce_flutter`. Five boxes (`progress`, `settings`, `reading_history`, `review_cards`, `practice_days`) store plain `Map` values (no TypeAdapters, so no build_runner). Each data source has `open()`, a `_requireBox` guard that throws `StorageException`, and migration-on-read (e.g., retired enum value rewrite in `settings_local_data_source.dart`; enums stored by `name`, never index).
- `sqflite ^2.3.0` (+ `sqflite_common`, `sqflite_common_ffi` on Windows/tests):
  - `QuranDatabase` copies the bundled `assets/data/quran.db` to `quran_v<schema>.db` in app support with an atomic copy, deletes older versions, and opens read-only.
  - `DownloadsDatabase` is the app's own writable `downloads.db`, which survives replacement of the bundled DB.
- `AssetReader` abstraction (pure Dart) + `BundleAssetReader` lets loaders run under `dart run` tools and tests with fixtures.

### Localization + RTL
- `easy_localization ^3.0.8`. `AppLocalization` sets supported `ar`, `en`; start locale `ar`; fallback `en`. Translations live in `assets/translations/ar.json`/`en.json` (692 lines each, same shape). `LocaleKeys` is generated by `tools/gen_locale_keys.py` (not easy_localization's codegen).
- `main.dart` sets `Intl.defaultLocale = context.locale.toString()` on every build and keys `MaterialApp.router` by locale to force a full relocalization. The tab index is kept in a DI `ValueNotifier` so the reader stays in Settings after switching language.
- RTL: `EdgeInsetsDirectional` is used throughout (247 directional vs 10 left/right; the 10 are symmetric values in custom painters, the splash, a gradient, and one in the admin tool). The contract also requires RTL-correct icons, sliders and progress. Widget tests assert that the app launches RTL and mirrors when forced to English.
- Digits: `toLocalisedString()` uses `ar_EG` for any Arabic locale so you get Arabic-Indic digits. `withLocalisedDigits()` rewrites intl-formatted dates and times. `joinDetails()` uses the Arabic comma, not the middle dot.
- Hardcoded strings: none in the app. The admin tool is English-only by design.

### Theming
- `lib/core/theme/app_theme.dart`: `AppTheme.light`/`dark` getters built from one `_build()` that takes a hand-built M3 `ColorScheme`. It sets component themes for `appBarTheme`, `dividerTheme` and `navigationBarTheme` (with `WidgetStateProperty`). The whole result goes through `WindowsDesign.apply()`.
- `lib/core/theme/app_colors.dart`: `abstract final class AppColors` holds all colour literals, each with a documented WCAG contrast ratio. `brand_contrast_test` recomputes the ratios and `colour_literal_test` forbids literals anywhere else (even `Colors.transparent` → `AppColors.transparent`).
- `lib/core/theme/app_text_styles.dart`: `.sp`-based getters (display, title, body, label). These are **unused**, since screens use `Theme.of(context).textTheme` 284 times. The file also declares `uiFontFamily = 'IqraWartaqUI'`, which pubspec does not declare (silent platform-font fallback), and holds the scripture styles (the only ones in real use).
- `lib/core/theme/windows_design.dart`: on desktop only, overlays Fluent geometry (4/8 radii, 32 px controls, compact density, Windows type ramp that keeps the existing colours) for buttons, inputs, cards, dialogs, menus, sheets, chips, list tiles, slider, scrollbar and tooltip.
- `lib/core/theme/window_chrome.dart`: sends the theme to the Windows runner over a `MethodChannel` to colour the title bar. It is deduplicated and swallows `MissingPluginException`.
- Dark mode: system/light/dark from settings.

### Responsive
- `flutter_screenutil ^5.9.3`. Design size from `_designSizeFor()` in `main.dart`: phone 375×812, tablet 768×1024 when `shortestSide >= 700`, desktop = the window itself (1:1, so no scaling; `didChangeMetrics` rebuilds on resize).
- `AppConstants.tabletBreakpoint = 600`: real window width (not `.w`) for 2→3 grid columns.
- `lib/core/desktop.dart`: `isDesktop` (from `defaultTargetPlatform`, so tests on a Mac still lay out as a phone), `DesktopWidth(maxWidth: 760)`, page width 640, two-page spread from width 1000.

### Text scaling
No global clamp (`ScreenUtilInit(minTextAdapt: true)`). Scripture text uses `TextScaler.noScaling` with the app's own text-size setting. The surah list clamps `textScalerOf(context).scale(1)` to 1.0–1.6 for computing row heights. The admin tool has its own scale control (`lib/admin/screen/admin_text_scale.dart`). A layout test covers the largest system font scale.

### Env / flavors
No flavors, no dotenv. `--dart-define` for `MANIFEST_URL`/`APP_INFO_URL` (with defaults) and, for the admin tool only, `R2_*`/`AUDIO_BITRATE` passed by `run_admin.sh`, which sources the gitignored `admin.env`. Missing admin keys stop the tool at launch, naming what is absent. The contract says a secret-looking literal in `lib/` fails a test.

### Logging
`dart:developer` `log(name: ...)` in 5 places and `debugPrint` in 6 places. No logger abstraction.

### Analytics / crash reporting
None, deliberately: the contract forbids analytics, crash reporting, Firebase and accounts.

### Push notifications
None.

### IAP / payments
None. No ads, by contract.

### Permissions
None. No `permission_handler`. The app needs no runtime permissions; audio is handled by `audio_service`.

### Deep links
None.

### Platform channels instead of packages
Used to keep the approved-package list short:
- `ShareService` (`com.example.app/share`): Android FileProvider + `ACTION_SEND`; iOS `UIActivityViewController`.
- `DocumentPicker` (`…/files`, Android only, returns a sealed `PickedText`).
- `KeepAwakeService` (`…/keep_awake`).
- `AudioStorage.excludeFromBackup` (`mirqat/storage`, iOS do-not-back-up flag).
- `WindowChrome` (`mirqat/window`).
- Admin `NSOpenPanel` (`mirqat/admin_files`).

All of them return `false` or no-op on `MissingPluginException`, which makes them test-safe. Each one needs native code in `android/`, `ios/` or `windows/`.

## 7. Quality notes

- **Null safety / Dart:** Dart 3.12 features are used throughout (sealed classes, switch expressions, patterns `if (x case final T v)`, records, `_` wildcards, `abstract final class`). Explicit types everywhere.
- **Lints:** stock `flutter_lints` with no extra rules. CI (`.github/workflows/ci.yml`) runs `flutter analyze --fatal-infos --fatal-warnings` and `flutter test` on main/dev/PRs. `release.yml` gates on the same checks and then builds the AAB and iOS from repo secrets. `bump-build-number.yml` auto-increments the build number.
- **Tests:** 126 test files. This is an unusually strong suite, including policy tests that turn the CLAUDE.md rules into executable checks (colour literals, contrast, fonts, no emoji, admin isolation, asset integrity, store release config, RTL/LTR launch, overflow at 320 dp and at the largest font scale). There are test harnesses for DI and localization (`test/app_harness.dart`, `test/localized.dart` mocking the shared_preferences channel for easy_localization).
- **Deprecated APIs:** none found (0 `WillPopScope`, `textScaleFactor`, `MaterialStateProperty`, `withOpacity`). Uses `WidgetStateProperty`, `withValues(alpha:)`, `toARGB32()`, `TextScaler`.
- **Duplication:** the `_guard<T>` try/catch → Either helper is repeated in 8 repositories. `ManifestService` and `AppInfoService` are near copies.
- **God files:** listed under SMELLS. The admin screen and cubit and the session cubit/bar/sheet are each about 1k lines or more.
- **Dead or misleading code:** the `AppTextStyles` UI getters are unused, and the `uiFontFamily` font is not declared in pubspec.
- **Docs drift:** the CLAUDE.md A.3 tree is behind the code (new features and services are not listed).
- **Comments:** very long prose doc comments on nearly every member. They capture intent well but are heavy if copied into a template.
- **Secret-like files at the project root:** `Certificates.p12`, `play_service.json`, `admin.env` (all gitignored and untracked; contents not opened). `admin.dev.example` is tracked. No secret literals found in `lib/`, `tool/` or `tools/`.
